# Следующий этап Galera

Базовая версия использует одну MariaDB. Galera не включена в текущую реализацию.

Расширение реализовать отдельным Compose-вариантом слоя приложения. Сохранить сеть `safeboard`, БД `kuma`, пользователя приложения и UID дашборда. Адрес Kuma и mysqld_exporter параметризован через `DB_HOST`; в кластерном варианте он указывает на `haproxy`.

1. Добавить три MariaDB/Galera с отдельными volumes и закреплённой версией wsrep provider. Секрет SST хранить отдельно.
2. Первично инициализировать ровно один узел и присоединить остальные. Повторный deploy не должен заново создавать кластер. После полной остановки проверять `safe_to_bootstrap` и позиции транзакций; не форсировать небезопасный bootstrap.
3. Добавить HAProxy, допускающий только Synced-узлы Primary-компонента. Использовать один writer и SQL только внутри Docker-сети.
4. Собирать метрики каждой ноды напрямую через multi-target mysqld_exporter. Добавить кворум, `wsrep_ready`, состояние узлов, размер кластера и доступность HAProxy.
5. Проверить отказ одной ноды, переключение writer, возвращение узла через SST/IST, потерю кворума при отказе двух узлов, полный shutdown и восстановление без потери данных.

Данные одиночной MariaDB переносить через проверенный backup/restore в новые volumes. Сохранённая резервная копия обеспечивает возврат к одиночной БД. Обычный `deploy-all` не должен автоматически преобразовывать рабочую БД в кластер.
